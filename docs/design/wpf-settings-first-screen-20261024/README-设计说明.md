# WPF 设置界面重设计 · 说明（2026-10-24，设计稿阶段，未改任何代码）

## 问题
1366×768（带任务栏）下，设置区域只有 632px，旧框架自己占 230px（顶部条 73 + 边距 36 + 固定页头 84 + 状态条 37），内容区只剩约 402px；左导航也被裁掉约 21px。结果：Square ≈1,240px、Linkly 后端异步 ≈1,650~1,900px、小票 ≈770px、数据维护 ≈566px、设备注册 ≈530~556px 等页，**功能按钮都在折线以下，要下拉才看得到**。

## 三招
1. **压缩框架**：顶栏 52（返回 + 面包屑 + 保存状态；页头并入）、边距 12、状态条 28、左导航 200 宽 / 48 高项（六项全可见）。
2. **固定底部操作条**：内容放不下的页，本页所有主操作（保存 / 检测 / 启用 / 更换分店…）钉在面板底部，永不滚动出视野；危险操作红色描边并与主操作隔开。内容放得下的页（数据维护、员工 App 下载）按钮留在各自说明卡片旁。
3. **双栏 / 三栏紧凑化**：输入框 52→44、开关行 72→56、分段页签 38→44，均 ≥ 触屏最小 44；动态列表（门店/设备/线路/诊断步骤）用固定高度内部滚动区，**滚动区里不放任何功能按钮**。

可用空间：旧「页签 + 表单 + 全部按钮」共用 402px，新为 页签 69 + 内容 392 + 底栏 65 = 526px（+124px，约 +31%）；无页签的页内容区 461px（含底栏）。

## 需要你拍板（我的建议在括号里）
1. **「环境」分段位置**：Linkly 放在子页签行右侧，Square 仍在页内。是否统一上移？（建议统一，Square 可再省空间）
2. **Linkly 把「三选一模式」和「连接优先级」合成一个 3 行列表**：点行 = 切换查看，⚙ = 设为首选，▲▼ = 调序；行顺序会随优先级变化。（建议接受；保留固定顺序的单选，后端模式放不下）
3. **Linkly 后端异步**要先点线路再点底栏按钮（比原来多一次点选）。（建议接受；行内按钮放不下）
4. **新增 resx 文案键**：Linkly 三种模式的短说明（中英各 3）、远程维护安装步骤（中英各 5）、设备注册入口状态（3）、Square 草稿芯片。不接受新增键的话要截断/保留原长文案。
5. **Square 两个同名「刷新状态」**（直连 / 设备码）：是否把直连那个改名「刷新直连状态」？
6. **小票条款页**我加了与门店信息页相同的「总部锁提示 + 同步」（原来条款页文本框同样只读却没有说明）。保留吗？
7. **设备注册里「一键修复 / 确认修改 / 还原修改」按钮不进底栏**（文案动态太长），留在网络检测卡内的固定状态区——是对「按钮全进底栏」的有意例外。
8. **旧的「刷卡机」下拉**在 Linkly 后端页保留了（选中即切换付款线路，与「使用此线路」重复）；产品同意可删，再省 44px。

## 落地提醒（此阶段只是设计稿）
- `SettingsView.xaml` 约 662 行有一个 `ScrollViewer` 包住所有分类，**要做固定底栏必须先改这一层结构**（每页自带 Grid：内容行 + 固定底栏行）；建议先做框架、再逐页迁移。
- `ApiServerSettingsPanel` 可能与登录页共用，拆分时要加开关隐藏内置按钮，不能直接删。
- 所有高度是**对 XAML 的静态估算 + Chrome 渲染**，字体用的是系统回退字体，WPF 的 Segoe UI 字宽略不同；英文版数据维护 Debug 稿只剩 11px 余量。落地后必须在 1366×768 + 任务栏、以及 125% 缩放的真机上复核，并保留 `VerticalScrollBarVisibility=Auto` 兜底。
- 现有测试断言开关高度 ≥48（新稿 56 ✓）；落地时每页再加「不滚动放得下」的视口测试（1366×632）。
- 各组详细对照表（原控件 → 新位置，逐条打勾）与 XAML 落地思路在各自的 `spec.md`：`g1-data-remote-app/`、`g2-payment-square/`、`g3-linkly/`、`g4-receipt-device/`。
