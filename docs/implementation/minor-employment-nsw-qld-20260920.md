# NSW / QLD 未成年用工实现说明

本地实现，未部署；未对生产数据库执行迁移，未向真实家长发送短信或邮件。

## 页面入口与流程

| 使用者 | 入口 | 功能 |
|---|---|---|
| 员工 App | 个人信息 → 未成年用工 | 学校、家长、备用联系人、其他工作、通勤及官方表单资料；保存草稿；生成并分享家长链接；签署后提交 HR |
| 家长 Web / 手机浏览器 | 员工分享的一次性链接 | 核对完整只读快照、确认监护关系/备用联系人/同意范围、手写签署 |
| HR Web | 系统 → 员工资料 → 未成年用工审核；`/system/minor-employment-review` | 分页、姓名搜索、州/状态筛选、完整档案、签署 PDF、版本审计、通过/退回字段和意见 |
| HR App | 员工资料审核 → 未成年用工审核 | 审核列表、详情、签署原件、版本历史、通过与退回 |
| 经理 App | 考勤/排班 → 未成年用工提醒 | 待处理、已升级、已知悉、已解除；规则依据；选填备注；确认知悉/升级 |

家长电话（手机或固定电话）和邮箱在发起签署、签署及提交时必填。紧急联系人共两人：家长及至少一名独立备用联系人。草稿允许逐步填写；家长电话不可与备用联系人的电话或手机重复。

状态：`draft → awaiting_guardian_signature → signed_pending_employee_submit → pending_hr_review → approved / returned`。已签资料修改必须新建档案版本，旧版本及签署 PDF 保持可查询。档案版本 `Version` 与同一草稿修改序号 `Revision` 分开；保存/邀请/提交/审核均检查相应并发状态。

## 提醒边界

- 排班新增、修改、发布及真实打卡均可继续。提醒不增加强制勾选、不要求填写继续原因。
- 提醒计算或落库失败不回滚已完成的排班/打卡，不把无结果显示为已确认合规。
- QLD 学龄儿童规则按评估日年龄、Year 10 及教育豁免判断适用范围，不能把所有未满 18 岁员工都套入同一上限。学校日和非学校日分别判断；周累计以周日开始，学校周和整周非学校周区分。夜间、同一雇主班间休息、校课冲突分别提示；普通零售未满 13 岁提醒 HR 核验特殊许可或例外。
- NSW 普通零售不套用 QLD 数值限制；保留教育出席、返程安全、适用 Award 待核实提示。
- 其他工作及本公司的计划/实际工时纳入评估。进行中的打卡按已工作时长加剩余排班预测评估，完成下班后由实际班段替换对应计划。只有总时数的外部工作不虚构具体上下班时间。学校日历、年龄适用范围或其他工时不明时明确提示资料待补充。
- 放学至店、返程和最晚交通安排属于安全提醒，不从法定工作时长中扣减通勤时间。
- 确认知悉保留风险；重新计算已不再出现的具体班次风险可转为已解除，历史动作保留。

本版本未接入员工适用 Award / enterprise agreement 的配置，因此对 Fair Work 相关的休息、最低班长等显示“需 HR 核验”，不能把该提示解释成已自动确认符合 Award，也不能把 QLD 数字当作 NSW 通用上限。

## 签署与原件

- QLD 使用随代码归档的官方 CE1 v4 四页模板并填充、扁平化；完整快照和签名作为附页保存。NSW 使用公司同意书，不冒充州政府统一表格。
- 家长链接使用 URL fragment，令牌在 POST body 中交换；服务端只存哈希，支持过期、一次使用及新版本撤销旧链接。
- 分享链接记录家长的自我声明与签署；本版本没有短信 OTP 或身份核验，也不自动发送消息。
- COS 上传显式签名 `x-cos-acl: private`，原件仅通过 HR 鉴权接口下载。服务端读回时核对签署 SHA-256；敏感响应禁止缓存。
- 并发签署失败时，核对数据库没有引用后清理本次随机对象。清理/引用核验失败保留对象并记录日志，需按精确 object key 人工检查；不得直接批量删除整个前缀。

## 2026-10-04 店长发起与监护人邮箱验证

- **店长发起**：考勤管理 › 未成年用工提醒 › 「未成年员工资料」列出可管理门店里按生日未满 18 岁的员工及档案进度，可「通知员工填写」/撤销。接口 `GET manager/candidates`、`POST manager/requests`、`POST manager/requests/{id}/cancel`，权限沿用排班提醒的 `Schedule.ViewStore` / `Schedule.EditManagedStore`，门店范围按可管理门店校验。同一员工只有一条未完成请求（过滤唯一索引兜底），员工提交 HR 审核时自动完成。员工端在未成年用工页顶部看到请求（`GET me/requests`）。
- **监护人邮箱链接**：发起签署默认 `deliverByEmail=true`，后端用发票邮箱后台配置的公司 SMTP 账号把签署链接直接发到监护人邮箱，成功时不把链接回传员工手机；发信失败或员工选择「改为转发链接」时才返回链接。链接有效期 App 默认 72 小时。
- **验证码与会话**：监护人打开链接后先看到只含打码邮箱的验证页（`POST guardian/session`），发验证码（`guardian/send-code`，10 分钟有效、60 秒冷却、每个链接最多 5 次）并校验（`guardian/verify`，错 5 次作废），通过后得到会话密钥（只存哈希、2 小时、存本标签页 sessionStorage）。`guardian/preview` 与 `guardian/sign` 都必须带会话密钥，转发出去的链接没有验证码也看不到孩子资料、无法代签。匿名接口按 IP 每分钟 30 次限流。
- **签署证据**：审计 `guardian_signed` 记录邮箱核验时间、打码邮箱、来源 IP、浏览器标识（截断）；`guardian_invite_emailed` / `guardian_code_sent` / `guardian_email_verified` 分别留痕。
- **监护人现场修改**：签署页默认只读核对，点「修改资料」可直接更正孩子资料、监护人资料（邮箱除外）、就读情况、学校安排、其他工作、通勤接送、备用联系人，改完随签名一起提交（`guardian/sign` 的 `amendments`），无需员工回 App 重填。后端逐项比对只记真正变化的：写回同一版本（Revision+1）、`GuardianAmendedFieldsJson` 记修改分区、审计 `guardian_amended` 存修改前后完整值（审计元数据改为 nvarchar(max)），PDF 按修改后内容生成。修改后照常校验联系人、备用联系人不同号、上学时间格式与必填资料，不通过则整单不写入。监护人邮箱（验证码依据）、出生日期（以员工资料为准）、雇主信息、州与表单类型不可改；其他工作的工时区间与学校时区保留原值。员工 App 与 HR（Web/App）显示「监护人签署时修改了：…」。
